# GPU residency bug journal

## 2026-11-25, Pacific time

- **15:38, source verification.** The default `Play-VIctory.cmd` and its `fast` selector use the same local release. Its SHA-256 matches the build from `pareto-rtx-fast` at `fabb872`. The live window showed 81.4 ms/frame for an interval with 4,463 draws/frame. This observation has no controlled scene match.
- **15:39, descriptor lifetime and idle pools.** Moved the bindless buffer sweep and its previous ranges onto their owning host heap. A list holds each stride buffer it uses. A deferred sweep verifies the stride buffer identity before reading a heap. The periodic budget check can now drain expired pieces and trim completely free blocks from the texture and upload pools. Busy allocators retry on their next opportunity.
- **15:41-15:42, initial comparison.** Both releases used fresh copies of the same opening save and warmed cache. The first comparison stopped each process when Windows commit headroom dipped below 2 GiB. Neither reached the 1,000 draws/frame threshold. The baseline reported 4,241 MiB of live texture staging, 277 MiB of commit headroom and 7,648 MiB of free physical memory in its pressure log. The first candidate reported 2,870 MiB of staging when it first signaled pressure, at a different frame. Those samples cannot quantify memory savings.
- **15:45, staging admission.** The pressure cap had applied before catch-up tripled the budget, and early prefetch could add its own allowance. On auto settings, the final shared budget now limits speculative staging to 16 MiB/frame under pressure or 32 MiB/frame on a limited-RAM host with at least 1 GiB of live staging. A single texture can cross the limit. Required material bakes keep their existing budget and explicit stage-budget overrides take precedence. The maintenance pass also releases all eligible spare staging blocks under host pressure. Release GPU suite: 329 passed, 34 ignored.
- **15:46-15:48, release comparison on the RTX 5090.** Repeated from the same copied save and the same initial cache with the normal Pareto rendering settings. Allowed transient Windows commit dips and stopped after 15 distinct title-bar intervals with at least 1,000 draws/frame. Baseline median 64.2 ms/frame, candidate 54.8. Both reached 50 ms or better in four intervals. Median draws/frame were 2,868 and 2,839. Peak process commit was 27.15 and 26.12 GiB. Sampled peak whole-adapter use was 18.67 and 17.45 GiB. The two runs progressed at different rates and window capture overlapped part of the baseline, so this pair is directional.
- **15:49-15:50, visual verification.** Window capture confirmed the candidate renders the opening street and characters with textures and colored lighting. In this longer capture run the median was 57.7 ms/frame over 23 heavy caption intervals, six at or below 50 ms. The slowest interval was 566 ms, peak process commit was 28.74 GiB, and sampled whole-adapter use peaked at 19.12 GiB. The original GDI captures returned white surfaces; Windows Graphics Capture returned the game image. PresentMon produced no events in this session, so there is no individual-present latency distribution. The two controlled releases used the same general shader and material paths. Wave64-to-Wave32 translation warnings remain in the logs. Sustained 50 ms/frame and full material coverage remain open.
- **Local build.** The optional launcher selector is `pareto-residency`. SHA-256 `4d5f1e9a0aa6d13c96dfdf69526c3128077588ed4f18df81f16bf3c8b3afc191`. Comparison receipts and window captures are under `../XCL-frame-timing/pareto-residency-comparison` relative to the checkout.
- **15:53, manual run.** Windows returned E_OUTOFMEMORY (0x8007000E) for a series of 64 MiB pool requests and individual uploads as small as 24,080 bytes. Rust subsequently aborted on a 786,432-byte allocation. The pasted log does not identify the Rust allocation site or a particular resource as the initial cause.
- **15:56–15:59, reproducer and repair.** Replayed eight reported upload sizes through the release pool with a failing block allocator. The unpatched test made eight block creation attempts in one burst. Each pool now backs off growth for 500 ms after a failed creation while still reusing space in its existing blocks. An out-of-memory return from host upload or texture allocation interrupts the descriptor texture sweep, leaving interrupted work eligible for retry. The sweep checks available Windows commit at most once per 32 ms, including during a long pass. It defers ordinary prefetch below 4 GiB and bake prefetch below 2 GiB; explicitly bound textures can still request upload memory. GPU unit and device suite: 331 passed, 34 ignored.
- **16:00–16:03, first opening-save retest.** Windows Graphics Capture showed a character, textured buildings and street lighting. The log contained no failed upload-buffer allocations or Rust allocation aborts. The harness timed out during shutdown and lost its timing receipt. The renderer logged a dropped draw due to exhausted dynamic descriptor slots.
- **16:04–16:07, confirmation and install.** From a fresh copy of the opening save, the release ran 135 seconds after the first interval above 1,000 draws/frame and remained live until the harness closed it. Peak process commit was 34.42 GiB; the lowest sampled Windows commit headroom was 1.30 GiB. Zero E_OUTOFMEMORY returns and zero Rust allocation aborts appeared in the log. Across 120 high-draw caption intervals the median was 54.3 ms/frame, with 39 at or below 50 ms. The descriptor-slot warning recurred. Installed and hash-verified the release behind the existing `pareto-residency` selector. SHA-256 `d580328bf90fe54e643dad60c04481d7e4b0d7134b9b6ce70c5e0f5c77ff3cf1`.
